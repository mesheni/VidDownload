# VidDownload v0.9 — UX/UI: устранение дублирования + информативность плейлистов

## Дизайн-спецификация (по ui-design skill)

1. **Purpose**: диспетчер загрузок видео/плейлистов. Пользователь должен мгновенно видеть состояние каждого элемента очереди; плейлист — как отдельная сущность с контекстом «видео N из M».
2. **Aesthetic Direction**: Industrial/utilitarian «terminal dashboard». *(Brand override, оговорён явно: сохраняем существующую идентичность приложения — тёмная тема + красный акцент + монопространственный Cascadia Code. Запрет скилла на «системные шрифты» не применяется: Cascadia Code — осознанный бренд, не generic default. Запреты на фиолетовые градиенты/emoji соблюдены.)*
3. **Color Palette** (выносится из inline-hex в общий словарь): фон `#1D1D1D`, поверхность карточек `#262626`/`#2B2B2B`, границы `#3A3A3A`; текст `#E8E8E8` / `#9A9A9A` / `#6A6A6A`; акцент `#FF5252` (+ тёмный `#BB1818`); статусы: Downloading `#42A5F5`, Paused `#FB8C00`, Completed `#66BB6A`, Failed `#E53935`, Cancelled `#757575`, Queued `#9E9E9E`.
4. **Typography**: Cascadia Code / Cascadia Code SemiLight (как сейчас): 13 bold — заголовки, 11 — мета-строки.
5. **Layout Strategy**: очередь — центральное пространство с «воздухом»; верх — компактный ввод; строка плейлиста — двухуровневая (плейлист → текущее видео). Единая палитра/шрифт для всех трёх окон.
6. **Icons**: Segoe Fluent Icons (системный, цель net10-windows10.0.22621) вместо текстовых глифов ▶⏸✕ из Segoe UI Symbol.

## Этап 1. Движок: парсинг плейлистов + флаги yt-dlp

**`Control/ParseLog.cs`** — новые compiled-регексы (после MergerRegex, до ProgressRegex):
- `PlaylistItemRegex`: `^\[download\]\s+Downloading\s+(?:item|video)\s+(?<n>\d+)\s+of\s+(?<m>\d+)` → группы n, m
- `PlaylistTitleRegex`: `^\[download\]\s+Downloading\s+playlist:\s+(?<title>.+)$`
- Поля плейлиста наследуются от `previous` (как percent/speed), обновляются при матче.

**`Services/DownloadProgress.cs`** — новые поля: `int? PlaylistIndex`, `int? PlaylistCount`, `string? PlaylistTitle`.

**`Control/Command.cs`** (LoadAudio + LoadVideo) — чекбокс «Плейлист» становится реальным переключателем:
- `isPlaylist == true` → добавить `--yes-playlist`
- `isPlaylist == false` → добавить `--no-playlist`

## Этап 2. Модель DownloadItem + прокидка в очереди

**`Services/DownloadItem.cs`** — новые `[ObservableProperty]`: `playlistTitle`, `playlistIndex`, `playlistCount`. Новые вычисляемые:
- `HasPlaylistInfo => PlaylistCount > 0`
- `DisplayTitle` → приоритет `PlaylistTitle`, затем `Title`, затем `Url`
- `CurrentVideoTitle` (подстрока «Видео: …» при плейлисте)
- `TotalPercent => HasPlaylistInfo ? (int)Math.Round(((PlaylistIndex - 1) * 100.0 + Percent) / PlaylistCount) : Percent` (clamp 0–100) — общий прогресс плейлиста
- `CanRetry` (Failed/Cancelled), `CanOpenLocation` (Completed && FilePath непуст)
- Каскады `OnPlaylist*Changed` → re-raise DisplayTitle/HasPlaylistInfo/TotalPercent

**`Services/DownloadQueueService.cs`** (callback прогресса, строки ~130–144):
- Прокидывать `PlaylistTitle/PlaylistIndex/PlaylistCount`
- При смене `PlaylistIndex` (пришло новое N ≠ текущего): `item.Percent = 0`, `item.Title = string.Empty` (следующий `Destination:` заполнит название нового видео — сейчас Title ставится только один раз `if IsNullOrEmpty`), затем `item.PlaylistIndex = n`. Это лечит «висящие 100% и название старого видео» между видео плейлиста.
