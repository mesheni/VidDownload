# Масштабный редизайн UI VidDownload: HandyControl → WPF-UI 4.3 (Fluent Design Windows 11)

## Принятые решения
- База: **WPF-UI 4.3.0** (нативная сборка net10.0-windows, совместима с проектом напрямую), HandyControl полностью удаляется.
- Акцент: **фирменный красный**, откалиброванный под Fluent (семейство #E5484D/#FF5252).
- Тема: **тёмная по умолчанию + переключатель Авто/Светлая/Тёмная** с сохранением в настройки.
- Типографика: Segoe UI Variable для интерфейса, Cascadia Code остаётся только там, где он уместен (URL, скорости, версии).

## Почему это безопасно
HandyControl используется фактически только для скинов, `MessageBox` и `Growl` — всё изолировано в сервисах (`IDialogService`/`IMessageService`/`INotificationService`) через DI, поэтому замена затрагивает точечные файлы. Локализация своя (resx), пакеты `HandyControl.Lang.*` уходят без потерь. MVVM-архитектура и все команды/биндинги не меняются.

## Шаг 1. Фундамент
1. **VidDownload.WPF.csproj**: убрать `HandyControl`, `HandyControl.Lang.en`, `HandyControls.Lang.ru`; добавить `WPF-UI` 4.3.0 (+ `WPF-UI.Abstractions` придёт транзитивно); Version → **0.9.0**.
2. **App.xaml**: убрать HC-словари и противоречивую конфигурацию (`StandaloneTheme AccentColor="#FFFFEFEF"` vs `Skin="Dark"` vs `SyncWithSystem`); подключить `<ui:ThemesDictionary Theme="Dark"/>` + `<ui:ControlsDictionary/>` + переписанный `/Themes/Colors.xaml`.
3. **Themes/Colors.xaml**: новая дизайн-система. Ключевой приём — **сохраняем все существующие ключи кистей** (`TextPrimaryBrush`, `AccentBrush`, `Status*Brush`…), чтобы биндинги и конвертеры работали без правок, но значения пересчитываем под Fluent. Добавляем новые токены: Card/SubtleFill/Strokes для светлой и тёмной темы (два словаря + переключаемый общий).
4. **AppServices.cs**: регистрация `ContentDialogService`, `SnackbarService` WPF-UI.

## Шаг 2. Сервисы диалогов и уведомлений (главная точка замены)
1. `HandyControlMessageService` → `ContentDialog`-реализация (`Ask/Info/Warning/Error`), тот же интерфейс.
2. `HandyControlDialogService` → аналог на `ContentDialog` с текстовым вводом где требуется.
3. `GrowlNotificationService` → `SnackbarService` (появление справа внизу); вопросы из snackbar переводим в ContentDialog.
4. `MainWindow.xaml.cs`: подтверждение выхода — на новую реализацию.
5. Хелпер `ThemeManager` (`Services/UiThemeService.cs`): применение Auto/Light/Dark через `ApplicationThemeManager` + фирменный акцент через `ApplicationAccentColorManager`.

## Шаг 3. Главное окно (переписывание MainWindow.xaml)
1. **`ui:FluentWindow`** с `ExtendsContentIntoTitleBar=True`: свой `ui:TitleBar` — иконка приложения, «VidDownload», справа переключатель темы (иконки sun/moon/auto) и системные кнопки свернуть/развернуть/закрыть. Обычный стеклянно-белый системный титлбар исчезает, окно получает скруглённые углы.
2. **Hero-строка URL**: крупное скруглённое поле (Cascadia Code, PlaceholderText), встроенная кнопка вставки из буфера, селектор языка рядом.
3. **Панель параметров**: две компактные группы/карточки; чекбоксы → **ToggleSwitch** (Win11-стиль), комбобоксы — родные Fluent, выровненная сетка вместо текущих разнобойных Margin'ов.
4. **Кнопка скачивания**: широкая accent-кнопка с глифом загрузки и HoVer/Drag-эффектами Fluent; вторичная кнопка «Очистить завершённые» — стиль Secondary.
5. **Карточки очереди**: скруглённые карты с аккуратной иерархией — цветной индикатор статуса (иконка + цвет), плавно анимированный прогресс-бар (анимация Value), плейлистовый бейдж, мета-строка моношрифтом, иконочные кнопки пауза/стоп/повтор/открыть/удалить в стиле Fluent IconButton.
6. **Виртуализация списка** очереди: `ItemsControl` в обычном ScrollViewer не виртуализирует — при больших плейлистах будет лагать. Переходим на `ListBox`+`VirtualizingStackPanel` (все команды остаются через биндинги).
7. Футер: моноширинные версии yt-dlp/ffmpeg + вторичные кнопки «История», «Конвертер», «Справка» с иконками.
8. Сохраняются: все `Command`-биндинги, KeyBindings Enter/Esc, AutomationProperties, `{Binding LocalizedStrings[...]}`.

## Шаг 4. Второстепенные окна
1. **ConvertWindow**: единный набор полей Fluent, секции как карточки, прогресс в стиле Fluent.
2. **HistoryWindow**: убираем захардкоженные цвета (#FF1D1D1D, #FF282828, …), таблица — стиль Fluent, тёмные шаблоны колонок уже есть — адаптируем.
3. **HelpWindow**: современная страница «О программе»: иконка, версия, красный акцент, ссылки (Github, лицензия), история изменений кратко.

## Шаг 5. Переключатель тем
1. Новая настройка `Appearance` ("Auto"/"Light"/"Dark") в `UserSettings` + сохранение через существующий `JsonSettingsService`.
2. Применение при старте в `App.OnStartup`; переключение кнопкой в TitleBar с цикличным выбором, применяется ко всем открытым окнам (`ApplicationThemeManager.Apply`).
3. Статусные цвета (StatusPalette.cs) проверяем на контраст в обеих темах — при необходимости добавляем лёгкие варианты кисти для светлой темы.

## Шаг 6. Очистка и мелочи
1. Пройти по всем XAML: удалить неймспейс `hc:`, атрибуты `hc:Theme.Skin` (26 шт.), заменить `hc:InfoElement.Placeholder` → `PlaceholderText`, `hc:ImageBlock` (HelpWindow) → обычный Image в скруглённом Border.
2. Синхронизировать статусные цвета между Colors.xaml и StatusPalette.cs (комментарий в файле обязывает).

## Шаг 7. Проверка
1. `dotnet build VidDownload.sln -c Release` — сборка всех 3 проектов.
2. `dotnet test` — 5 тестовых файлов логики должны пройти без изменений.
3. **Визуальная верификация**: запустить приложение и проверить его appearance через screenshot/computer-use — главное окно, карточки очереди, диалоги, переключение Light/Dark, открытые вторичные окна. Регрессии чинить на месте.

## Риски и их обработка
- **Mica** работает только на Windows 11 (22H2+): WPF-UI сам падает на сплошной фон при отсутствии поддержки — код деградации не нужен, только проверка внешнего вида.
- Неявные стили WPF-UI меняют вид ВСЕХ стандартных контролов сразу (в этом и суть) — отдельно проверяем Convert/History/Help окна, где остались голые TextBox/DataGrid.
- `ContentDialog` требует привязанного DialogHost на каждом окне — делаем маленький attached-behavior/helper и вызываем на Loaded.
- Одиночная пабликация self-contained сохраняется; WPF-UI корректно работает с PublishSingleFile.

Итог: ~14 изменённых файлов, 3–4 новых, пакетов меньше на 2. Результат — актуальный Fluent-интерфейс Windows 11 с фирменным красным и живыми анимациями вместо плоской «утилитарной» темы HandyControl.
